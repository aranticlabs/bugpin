# Widget Changelog v1.2.0

## Heads up before upgrading

- Screen recording and duplicate-safe retries need BugPin 1.3.0 or later. Screen recording is off by default; turn it on in the Admin Console under **Widget > Recording**, or per project under **Project Settings > Recording**.
- The hosted `/widget.js` served by BugPin 1.3.0 already includes these changes. This release is for the `@arantic/bugpin-widget` npm package.

## Features

### Screen recording

- Reporters can record the page from a new **Recordings** tab and attach the clip to their report, with optional microphone audio.
- A recording toolbar offers a 3-second countdown, pause and resume, stop, and discard, plus a pen with five colors, undo, and clear, a laser pointer, and click effects.
- Toolbar shortcuts use Alt (Option on macOS) with V, P, L, C, and Z, so plain keys keep reaching the page being recorded. Esc returns to the cursor.
- In browsers with Element Capture, the toolbar, the red recording frame, and widget notifications stay out of the video when the current tab is shared. Sharing a whole screen shows a warning.
- Recording stops on its own at the duration limit or shortly before the upload size limit, and a clip that is still too large keeps **Submit** disabled until it is removed.
- Recordings survive a crash or reload: the clip is stored in the visitor's browser while recording and restored the next time the widget loads, with a badge on the launcher. Stored clips are deleted after submit or removal and expire after 7 days.
- Uploads show a progress bar and can be canceled.
- The **Recordings** tab shows the recording quality set in the Admin Console, and each clip lists its quality, length, and size.

## Changed

- Reports include each screenshot's and video's capture time, dimensions, length, and recording quality, which BugPin 1.3.0 shows in the report detail. Older servers ignore them.
- The widget accepts MOV uploads, and no longer offers AVI, which the server never accepted.
- When the widget cannot reach the server, it says the report was saved and will be sent automatically, instead of showing the success message.
- When an upload is rejected on the way, for example by a reverse proxy size limit, the widget says so and asks the reporter to remove or shrink attachments, instead of queuing a report that never arrives.

## Fixes

- Reports retried from the offline buffer are no longer created twice: each report carries a submission id, and the server answers repeats with the existing report.
- Buffered reports are no longer sent twice when several tabs, or a slow upload and the next retry, overlap.
- The widget no longer appears on sites whose project is paused. Before, it showed with default settings and every submission was rejected.

## Maintenance

- A new CI workflow checks that the widget bundle stays under 190KB gzipped (`bun run check:widget-size`).
- Removed debug logging from screenshot capture and an unused component.
