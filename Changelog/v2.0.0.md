# Changelog v2.0.0

## Heads up before upgrading

- The Admin Console navigation is new. All settings moved into a separate **Settings** area, and old links redirect to the new pages.
- Webhooks moved from **Settings > Webhooks** to each project's **Integrations** tab.
- The **Project Settings** and **Integrations** dialogs are replaced by a page for each project at `/projects/<id>`.
- The database is updated automatically on first start. Back up `data/` before upgrading.
- BugPin 2.0.0 serves the same widget as `@arantic/bugpin-widget@2.0.0` on npm.
- Launcher offsets, dialog texts and colors, and Reporter Portal links are set in the Admin Console and need BugPin 2.0.0. With older servers the widget uses its defaults.
- Pending database migrations create one verified snapshot beside the database, named `<database>.pre-upgrade-*.bak`, before bootstrap or migration changes. Fresh installs do not create upgrade snapshots. Allow free space of at least the database size plus 20%. Startup waits for the backup and integrity checks; duration depends on database size and disk speed. Repeated failures retain the first and latest verified snapshots for each migration state. Successful upgrades retain the latest two snapshots.
- To restore after an upgrade failure: stop BugPin, preserve the failed database and its `-wal` and `-shm` files separately, and copy the chosen `.bak` file to the configured database path. Do not leave the failed database's `-wal` or `-shm` files at that path. Restore file ownership and permissions, then restart the previous BugPin version. The snapshot restores the database only; keep your separate backup of uploaded files.
- Gamification is off after upgrading. Turn it on under **Settings > System > Gamification**. Past reports count toward levels and achievements right away.
- Editors and viewers need an administrator to allow API access before they can use API tokens (Enterprise Edition). Users who already had an active token keep access.
- Password reset emails require SMTP and the **Application URL** to be configured under **Settings > System**.
- If **Enforce HTTPS** locks you out, start BugPin with `DISABLE_HTTPS_ENFORCEMENT=true`, turn the setting off, then remove the variable and restart.
- The Reporter Portal is available per project after configuring a secure **Application URL** and SMTP. Existing reports are not automatically exposed. Use the report owner controls to grant access to historical reports, or **Make existing reports claimable** under **Settings > Project Defaults > Reporter Portal**. A separate **Portal Base URL** is recommended for production. See the [Reporter Portal guide](https://docs.bugpin.io/configuration/reporter-portal).
- `TRUST_PROXY` controls whether BugPin trusts `X-Forwarded-Proto` and forwarded client addresses. Only `token` mode honors `X-Forwarded-Host` from an authenticated proxy. In `auto` or `true` mode, configure the proxy to preserve the public `Host` header and send the public scheme in `X-Forwarded-Proto`. Older quick-start deployments may still use `false`. For a single-container deployment behind a trusted private-network proxy, set `auto` and recreate the container. Use `true` only when access is restricted to a trusted proxy. Keep `false` for directly exposed servers.
- If a proxy upgrade causes redirect loops, 403 or 421 responses, restore the configured public **Application URL** and **Portal Base URL**, correct the forwarded headers and `TRUST_PROXY`, then restart. For an HTTPS-setting lockout, use the temporary `DISABLE_HTTPS_ENFORCEMENT=true` recovery path above. It does not bypass host routing or origin checks.
- A **Portal Base URL** requires a valid **Application URL**. Clear the Portal Base URL before clearing the Application URL. To recover from a previously saved or restored portal-origin lockout with the standard Compose stack, run `docker compose stop bugpin-server`, then `docker compose run --rm --no-deps bugpin-server bun run reset-portal-origin`, then `docker compose up -d bugpin-server`. With `deploy/docker-compose.single.yml`, use that Compose file and substitute `bugpin` for `bugpin-server` in all three commands. Source installations can stop BugPin, run `DATA_DIR=/path/to/existing/data bun run reset-portal-origin`, then restart. The command requires an absolute DATA_DIR, clears only the portal origin in the existing database, and never initializes configuration, secrets, storage, or migrations. Correct the Application URL in the Admin Console before configuring a separate portal origin again.
- Team sign-in to the Reporter Portal is on by default while the portal uses the **Application URL**. With a separate **Portal Base URL** it stays off until an administrator turns it on under **Settings > System > General**.
- When moving from the 1.x `bugpin` container to the 2.0 Compose stack, stop the old container first so only one server uses `./data`. Use the 1.x Compose file to stop it, or run `docker compose down --remove-orphans` in the same Compose project. Back up `./data` while BugPin is stopped. With the 2.0 `docker-compose.yml`, run `docker compose pull && docker compose up -d` to start `bugpin-server` and `bugpin-admin`. The optional `bugpin-portal` service uses the `separate-portal` profile. The single image is still published. Examples for a single image, a separate portal host and a private server are in `deploy/`.
- Images are published as `x.y.z`, `x.y` and `latest`. The major-only tag (for example `2`) is no longer published.
- On first start, migration 021 rewrites Unix/Docker-style paths that end in BugPin's expected upload directory, report ID and stored filename to paths relative to the data directory. If a file is still available only at its original absolute path, BugPin keeps that path. Windows paths with backslashes, other directory layouts and object storage URLs keep their existing values.

## Features

### Reporter Portal

- Reporters sign in with single-use email links and an explicit **Continue** action. Requested links last 15 minutes; confirmation and invitation links last 24 hours.
- **My reports** lists reports with status tabs and counts, search, sorting, a project filter and a board view, marks new replies, and updates live.
- Each report shows the original report, its details, the page and browser captured with it, and the conversation with status changes in line. Screenshots and videos open in a lightbox.
- Reporters can reply with images or videos and submit new reports to eligible projects.
- Reporters can change their display name, language, email updates and light, dark or system theme. The portal and widget links support eight languages.
- **Team sign-in:** BugPin users sign in with their account for a read-only view of reporters' reports. The first sign-in confirms their email, and two-factor authentication applies. The Admin Console user menu links to it.
- Reporter Portal defaults under **Settings > Project Defaults > Reporter Portal**, which each project can override.
- The portal follows the Admin Console's branding: logos, app name, favicon, light and dark button colors (Enterprise Edition) and white-label footer.
- The Admin Console provides project portal settings, ownership and moderation controls, reporter activity indicators, and reporter suspension, session revocation and deletion.
- Email confirmation and one-click unsubscribe keep sign-in credentials out of staff CC copies.
- A separate portal origin isolates reporter sessions from the Admin Console. Private files require authorization, including HEAD and range requests.

### Deployment

- Separate server, Admin Console and Reporter Portal Docker images, with unprivileged Nginx frontends.
- `TRUST_PROXY=token` honors forwarded headers only with a proxy token. The token is shown under **Settings > Access > Network** and can be regenerated there.
- `APP_URL` fills an empty **Application URL** at startup. A URL saved in the Admin Console always wins.

### Dashboard

- A new dashboard with key figures (active, new, resolved, median time to resolve), intake vs resolution and priority charts, and an activity feed. Filter it by project and by the last 7, 30 or 90 days.
- **Needs attention**, **Assigned to you** and **Recent** list the most urgent reports. Assign or resolve reports straight from the dashboard.
- **Your time to resolve** compares your resolution times with the team's.

### Gamification

- Editors and admins earn XP for resolving reports, climb ten levels from **Newcomer** to **Legend**, and unlock eight illustrated achievements.
- The **Hunter's log** shows your levels, achievements and a team ranking.
- Administrators control gamification for the workspace and per user. Users can opt out in their profile.

### Settings area

- **Settings** opens a dedicated area grouped into **Account**, **System**, **Project Defaults**, **Access** and **Customization**, with a page for each setting. Editors and viewers see **Account** only.
- Profile, two-factor, password and notification settings moved from dialogs to pages.
- Preferences such as theme, sidebar width and panel states are saved per user and follow you across browsers and devices.

### User management

- Each user has their own page for account, role, security and API access.
- Administrators can send a password reset email, set a temporary password, sign a user out of all sessions, and allow or revoke API tokens (Enterprise Edition).

### Workspace

- **Projects** is a sortable, searchable table available to every role, with bulk actions for admins.
- Pin projects to the sidebar and drag them into your preferred order.
- New sidebar **Views** (**Assigned to me**, **Unassigned**, **Open**) with live counts, and a **Recent** list of reports you opened.
- The **Reports** page can switch to a board view. Drag reports between columns to change their status.

### Project pages

- Each project has its own page with tabs for reports, general settings, launcher, dialog, language, capture, notifications and integrations.
- A **Custom** switch on each card decides whether the project overrides the project defaults or inherits them.
- Launcher and dialog settings show a live preview of unsaved changes.

### Widget

- In projects with the Reporter Portal, the email field explains how to track the report.
- After submission, the widget offers **View my reports** when the portal is enabled. Reporters who provided an email address also see sign-in instructions.
- Launcher offsets can be set horizontally and vertically, in `px` or `rem`, and respect screen cutouts on mobile devices.
- Dialog title, placeholders and submit button text can be customized and translated per language. The priority field can be hidden.
- Secondary buttons and tabs have their own colors for light and dark mode.

### Capture and data

- Diagnostics (activity trail, console output, network failures, storage keys) can be set as project defaults under **Settings > Project Defaults > Capture** and overridden per project.
- Administrators can delete all reports and files under **Settings > System > Privacy & Data** while keeping projects, users and settings.

### Unsaved changes

- Settings and project pages save through one **Unsaved changes** bar. Leaving a page with unsaved changes asks whether to save or discard them.

## Changed

- Select fields are a keyboard-friendly list with typeahead that opens upward when there is no room below.
- Launcher tooltips appear after a short delay and fade in.
- The **Powered by** link uses the brand color.
- Screenshot size reduction moved from the dialog into an **Image size** menu (**Full size** / **Reduced size (1x)**) on the screenshot capture bar. Oversized screenshot warnings now appear inline on the capture bar so you can switch to **Reduced size (1x)** and retry without returning to the dialog.
- The microphone toggle moved from the Recordings tab onto the recording capture bar so reporters can turn audio on or off right before starting.
- Cards no longer have their own **Save** buttons; the **Unsaved changes** bar saves the whole page.
- **Allowed Domains** on a project can always be edited and warns when the list is empty.
- Report status and priority show as an icon with a label instead of colored badges.
- Refreshed interface: Geist font, breadcrumbs in the page header, animations for dialogs and menus, and consistent disabled controls. Keys, tokens and codes use Geist Mono.
- Changing your own email address requires your current password.
- Saving a settings page only sends changed fields, so it no longer overwrites changes made in another tab.

## Fixes

- Screen sharing exits cleanly when the browser cannot start the capture.
- The capture shortcut leaves the host page's keyboard action available when the widget cannot take a screenshot.
- Shift+Ctrl+Z and Shift+Command+Z redo changes in the annotation editor.
- **Reduced size (1x)** now also downscales screenshots captured with the Screen Capture API.
- Editors and viewers now see all projects in the Reports filter and in their notification settings.
- Launcher tooltips stay within the viewport.
- Turning off **Custom** on a project now removes the override.
- Saving a resolved or closed report keeps who resolved it and when.
- The **License** page shows why a license is inactive.
- Screenshots and attachments no longer return 404 when the data directory is mounted or restored at another path.

## Security

- Per-user API access is enforced for all API token requests.
- Password reset links are stored as hashes, expire after 24 hours and work only once.
- SMTP passwords, S3 secret keys and webhook secrets are no longer sent to the browser.
- Resetting a user's password or two-factor authentication revokes their API tokens.
- The last active administrator can't be demoted, deactivated or deleted.
- The dashboard no longer exposes email addresses and is rate-limited.
- API requests accept only known fields.
- The Admin Console sign-in and team sign-in share one attempt limit per address.
- Team sessions use their own cookie. They end on password changes, two-factor resets, deactivation, email changes and sign-out everywhere.
