# Changelog v2.0.0

## Heads up before upgrading

- The Admin Console navigation is new. All settings moved into a separate **Settings** area, and old links redirect to the new pages.
- Webhooks moved from **Settings > Webhooks** to each project's **Integrations** tab.
- The **Project Settings** and **Integrations** dialogs are replaced by a page for each project at `/projects/<id>`.
- The database is updated automatically on first start. Back up `data/` before upgrading.
- Gamification is off after upgrading. Turn it on under **Settings > System > Gamification**. Past reports count toward levels and achievements right away.
- Editors and viewers need an administrator to allow API access before they can use API tokens (Enterprise Edition). Users who already had an active token keep access.
- Password reset emails require SMTP and the **Application URL** to be configured under **Settings > System**.
- If **Enforce HTTPS** locks you out, start BugPin with `DISABLE_HTTPS_ENFORCEMENT=true`, turn the setting off, then remove the variable and restart.

## Features

### Dashboard

- A new dashboard with key figures (active, new, resolved, median time to resolve), intake vs resolution and priority charts, and an activity feed. Filter it by project and by the last 7, 30 or 90 days.
- **Needs attention**, **Assigned to you** and **Recent** list the most urgent reports. Assign or resolve reports straight from the dashboard.
- **Your time to resolve** compares your resolution times with the team's.

### Gamification

- Editors and admins earn XP for resolving reports, climb ten levels from **Newcomer** to **Legend**, and unlock eight illustrated achievements.
- The **Hunter's log** shows your levels, achievements and a team ranking.
- Administrators control gamification for the workspace and per user. Users can opt out in their profile.

### Settings area

- **Settings** opens a dedicated area grouped into **Account**, **System**, **Project Defaults**, **Access** and **Customization**, with a page for each setting. Editors and viewers see **Account** only.
- Profile, two-factor, password and notification settings moved from dialogs to pages.
- Preferences such as theme, sidebar width and panel states are saved per user and follow you across browsers and devices.

### User management

- Each user has their own page for account, role, security and API access.
- Administrators can send a password reset email, set a temporary password, sign a user out of all sessions, and allow or revoke API tokens (Enterprise Edition).

### Workspace

- **Projects** is a sortable, searchable table available to every role, with bulk actions for admins.
- Pin projects to the sidebar and drag them into your preferred order.
- New sidebar **Views** (**Assigned to me**, **Unassigned**, **Open**) with live counts, and a **Recent** list of reports you opened.
- The **Reports** page can switch to a board view. Drag reports between columns to change their status.

### Project pages

- Each project has its own page with tabs for reports, general settings, launcher, dialog, language, capture, notifications and integrations.
- A **Custom** switch on each card decides whether the project overrides the project defaults or inherits them.
- Launcher and dialog settings show a live preview of unsaved changes.

### Widget

- Launcher offsets can be set horizontally and vertically, in `px` or `rem`, and respect screen cutouts on mobile devices.
- Dialog title, placeholders and submit button text can be customized and translated per language. The priority field can be hidden.
- More dialog colors: secondary buttons and tabs, for light and dark mode.
- The priority selection supports keyboard navigation.

### Capture and data

- Diagnostics (activity trail, console output, network failures, storage keys) can be set as project defaults under **Settings > Project Defaults > Capture** and overridden per project.
- Administrators can delete all reports and files under **Settings > System > Privacy & Data** while keeping projects, users and settings.

### Unsaved changes

- Settings and project pages save through one **Unsaved changes** bar. Leaving a page with unsaved changes asks whether to save or discard them.

## Changed

- Cards no longer have their own **Save** buttons; the **Unsaved changes** bar saves the whole page.
- **Allowed Domains** on a project can always be edited and warns when the list is empty.
- Report status and priority show as an icon with a label instead of colored badges.
- Refreshed interface: Geist font, breadcrumbs in the page header, animations for dialogs and menus, and consistent disabled controls.
- Changing your own email address requires your current password.
- Saving a settings page only sends changed fields, so it no longer overwrites changes made in another tab.

## Fixes

- Editors and viewers now see all projects in the Reports filter and in their notification settings.
- Launcher tooltips stay within the viewport.
- Turning off **Custom** on a project now removes the override.
- Saving a resolved or closed report keeps who resolved it and when.
- The **License** page shows why a license is inactive.

## Security

- Per-user API access is enforced for all API token requests.
- Password reset links are stored as hashes, expire after 24 hours and work only once.
- SMTP passwords, S3 secret keys and webhook secrets are no longer sent to the browser.
- Resetting a user's password or two-factor authentication revokes their API tokens.
- The last active administrator can't be demoted, deactivated or deleted.
- The dashboard no longer exposes email addresses and is rate-limited.
- API requests accept only known fields.

## Maintenance

- Added `recharts`, `tw-animate-css` and `@radix-ui/react-slider`.
- The Admin Console uses React Router's data router.
- Expanded test coverage, and server tests are type-checked strictly.
